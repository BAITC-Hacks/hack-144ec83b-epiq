# Граф денег

[![CI](https://github.com/BAITC-Hacks/hack-144ec83b-epiq/actions/workflows/ci.yml/badge.svg)](https://github.com/BAITC-Hacks/hack-144ec83b-epiq/actions/workflows/ci.yml)

Локальный аналитический инструмент для восстановления структуры финансовой сети по обезличенным внутрибанковским переводам. Система присваивает каждому узлу объяснимую роль, строит кластеры и формирует очередь ручной проверки для AML аналитика.

Выводы системы являются гипотезами по наблюдаемому графу. Они не устанавливают личность, виновность или фактическое руководство группой.

## Быстрый запуск

Требуется Python 3.10 или новее.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -e .
money-graph --data ./data --out ./out
streamlit run app.py
```

В папке `data` должны находиться `nodes.parquet`, `edges.parquet` и `transactions.parquet`.

## Сценарий аналитика

1. Откройте топ-лист и выберите участника.
2. Отфильтруйте кандидатов по приоритету и сигналам: сбор средств, веерные переводы, транзит, связь с несколькими seed или высокий оборот.
3. Проверьте обоснование: число плательщиков, получателей и долю переведённого дальше объёма.
4. Откройте «След денег», чтобы увидеть путь от известного seed, и «Операции», чтобы проверить хронологию переводов.
5. Назначьте решение: углублённая проверка, запрос в правоохранительные органы или оба действия.
6. Добавьте участника в перечень и выгрузите итоговый CSV.

Расчёт создаёт:

- `nodes_roles.csv` — роль, сила признаков, кластер, приоритет и объяснение каждого узла;
- `clusters.csv` — размер, число seed, внутренний оборот, лидеры и гипотеза кластера;
- `top_nodes.csv` — первые 20 узлов для проверки;
- `node_features.csv`, `edges.csv`, `quality_report.json`, `run_manifest.json` для интерфейса и аудита;
- `route_patterns.csv` — сильнейшие наблюдаемые маршруты A→B→C;
- `resilience.csv` — стресс-тест удаления топовых узлов.

## Что рассчитывается

Граф остаётся направленным и взвешенным. Признаки включают число контрагентов, суммы и количество операций, достижимость из seed, PageRank, приближённое посредничество, энтропию распределения исходящих сумм и временные границы активности.

Кластеры определяются Louvain на отдельной ненаправленной проекции, где встречные денежные потоки суммируются. Роли назначаются прозрачными экспертными правилами. Приоритет объединяет охват seed, оборот, посредничество, связность и силу ролевых признаков.

### Критерии ролей

| Роль | Минимальное условие |
|---|---|
| `consolidator` | не менее 3 разных плательщиков |
| `distributor` | не менее 5 разных получателей |
| `transit` | отношение выхода ко входу 0,8–1,2; узел не seed и не `depth=4` |
| `terminal` | выход не больше 10% входа; после последнего входа наблюдаются ещё 2 дня |
| `coordinator` | достижим из 2+ seed, входит в верхние 10% по посредничеству и соединяет 2+ кластера |
| `peripheral` | ни одно правило содержательной роли не выполнено |

`priority_score` складывается из охвата seed (30%), оборота (25%), посредничества
(20%), связности (15%) и силы роли (10%). Полные формулы приведены в
[архитектуре](docs/architecture.md).

### Дополнительный анализ

- операции прихода и ухода в один день и в окне до двух дней;
- синхронные переводы от нескольких плательщиков и дневные всплески;
- циклы и сильнейшие двухшаговые маршруты;
- аномальность оборота и связности относительно узлов того же колена;
- устойчивость сети после удаления топ-1, топ-5, топ-10 и топ-20 узлов;
- рекомендация, какие данные запросить следующими;
- локальный помощник для вопросов о консолидации, распределении, транзите и координаторах.

Подробности и ограничения описаны в [архитектуре](docs/architecture.md).
Проверка соответствия исходному заданию приведена в [чек-листе ТЗ](docs/tz-compliance.md),
а порядок пятиминутной защиты — в [сценарии демо](docs/demo-script.md).

## Важные ограничения данных

- У `depth=4` дальнейшие исходящие переводы неизвестны, поэтому такие узлы не считаются конечными получателями только из-за нулевого выхода.
- Входящие потоки seed неполны; отношение исходящей суммы к входящей для них не используется в ролевых правилах.
- Одинаковые строки transactions сохраняются, поскольку без transaction_id нельзя доказать, что это технические дубли.
- Достижимость в графе не доказывает прохождение одной и той же денежной суммы по всему маршруту.
- `role_score` не является откалиброванной вероятностью: размеченных ролей в данных нет.

## Проверка

```bash
pip install -r requirements-dev.txt
pytest -q
```

На контрольной поставке пайплайн должен сохранить все 2 248 gid, включая изолированные seed, создать не менее 20 строк топа и завершиться менее чем за пять минут. Manifest записывает контрольные суммы входных файлов, версии библиотек и длительность расчёта.
