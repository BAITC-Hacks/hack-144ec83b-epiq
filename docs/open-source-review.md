## Что изменено в нашей реализации

Раньше быстрый поток любого контрагента посредника B помечал все маршруты через B.
Теперь `route_evidence.py` ищет реальные операции только на рёбрах A→B и B→C.
Выход до входа исключается. Для разрыва 1–2 дня порядок известен на уровне дат;
для нулевого разрыва он помечается неизвестным. Подбирается воспроизводимый пример
с датами и суммами. Диапазон выход/вход 0,8–1,2 — наша эвристика сопоставимости,
а не перенесённое правило Neo4j или нормативное требование.

Проверка выполняется для 200 крупнейших структурных маршрутов. Это не полный
поиск временных цепочек на четыре колена. Она не доказывает происхождение денег:
нет остатка счёта, времени внутри дня и идентификаторов отдельных транзакций;
разбиение и объединение нескольких платежей пока не сопоставляются.

Для кольцевого анализа также остаётся ограничение: `cycle_size` — размер
сильносвязной компоненты, а не длина единственного простого цикла. Временной
порядок полного кольца пока не проверяется.

## Самостоятельность и проверяемость

В этой доработке заимствованы общие идеи, реализация и тестовые примеры написаны
под текущую схему данных. Источники указаны выше; зависимости проекта перечислены
в pyproject.toml. При будущем переносе конкретного кода или ресурсов необходимо
отдельно проверить лицензию, сохранить обязательные уведомления и указать файлы.
Открытая лицензия не заменяет правила хакатона. Результат проверки на антиплагиат
неизвестен; переименование чужого кода ради её обхода не применяется.
